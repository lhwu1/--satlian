# 沿线：素材与地图编辑器方案

目标是让用户复用原有场景素材，也能让 AI 按统一协议制作新的枪械、材质、道具和可拼装的场景模块，再在编辑器里组合地图、设置天气并导出。AI 的具体交付规范见 [AI 素材生成指导](AI素材生成指导.md)。

本文是**设计方案，不代表编辑器、素材格式或导入器已经实现**。示例中的字段是拟定的 v1 协议；现有游戏不能直接读取。原始 `index.html` 保持不变，编辑器、适配器和加载器在独立目录开发，游戏接入也从副本或独立程序开始。

## 1. 工作流程

1. 扫描并预览原场景，将能独立创建的素材登记到只读的内置库，记录真实 ID、尺寸、材质依赖与适配状态；不能独立创建的先标为待拆分。
2. 用户在编辑器选择素材并摆放；缺少素材时，向 AI 提供指导文档、当前库清单和需求，让 AI 生成一个或一组素材包。
3. 导入器校验格式、版本、引用和预算，隔离预览；通过后用户确认入库。失败给出可定位的错误，保留原文件，不覆盖已有素材。
4. 将内置与新增素材实例拖入地图，调整位置、碰撞、出生点和天气；保存工程，重新打开后结果一致。
5. 地图校验通过后打包依赖；同一套解释器供编辑器预览和游戏加载，避免画面与碰撞各用一套逻辑。

```mermaid
flowchart LR
  Original[原始场景] --> Adapter[只读适配器与内置素材清单]
  AI[AI 按指导生成素材包] --> Check[校验与隔离预览]
  Adapter --> Library[版本化素材库]
  Check -->|用户确认| Library
  Library --> Editor[地图编辑器]
  Editor --> Project[地图工程与天气配置]
  Project --> Runtime[共享解释器 / 游戏加载器]
```

## 2. 可复用的现状与适配工作

原始 `index.html` 内含 three.js、程序化材质、几何拼装和场景逻辑。其 `gM` 将材质、关卡、道具、武器等模块用于 `showcase`，可作为预览实现的参考。现有名称和内部函数经压缩，**不等于稳定的公开接口**，需要在副本中逐项验证并包装，不能仅凭名称宣称所有组件都能直接拖入编辑器。

- 材质：现有底材和命名预设由材质系统生成，`mats.get` 在场景中被使用；先核对真实预设及参数，再建立 ID 映射。潮湿、纹理平铺和环境反射须在预览中考虑。
- 道具：场景用基础几何、材质和放置逻辑拼出箱子、油桶、叉车等。现有 `forklift`、`generator` 等名称可作为盘点起点；逐个验证创建入口、局部原点、包围盒和碰撞，不能将占地表中的名称直接当成已完成的工厂。
- 枪械：PAC-9 第一人称模型可作为姿态和材质参考；零件、瞄准点、枪口及动画绑定必须通过适配器明确暴露。
- 世界：天空、雨、海、地面与远景各有独立逻辑，但未必都可按任意参数配置；先验证现有能力，不能把示例参数当作当前实现。码头地面存在世界坐标相关效果，自定义地图需有独立的基础地面与边界。

内置库记录来源、原始标识、适配器版本和许可信息；新增内容使用独立命名空间。素材库可查询 ID、类型、版本、预览、尺寸、碰撞和依赖；素材实际可用性以适配器验证结果为准。

## 3. 素材、场景模块和地图

统一采用指导文档中的 `along.asset/1` JSON 素材包。一个包可含多个素材和依赖，常见类型：

| 类型 | 作用 | 预览与编辑 |
| --- | --- | --- |
| `material` | 可复用的材质参数或受支持的程序化配方 | 干/湿球、板和现有道具 |
| `prop` | 箱子、门、掩体、建筑构件等单体 | 多角度、尺寸、材质槽和碰撞 |
| `weapon` | 第一人称枪械外形与绑定点 | 全枪、腰射、瞄准、枪口；数值与玩法分开 |
| `scene_module` | 可重复摆放的一段建筑或小场景，如仓库一角 | 展示完整构件、入口、包围盒和碰撞；不包含整张地图的全局天气 |

地图工程使用 `along.map/1`，包含地图尺寸、素材实例及其精确版本、变换、碰撞、出生点、区域和世界配置。地图是素材的组合，不把每次摆放复制成新素材。一个独立房间或仓库片段作为 `scene_module` 入库；整张可玩的地图作为 `along.map/1` 工程保存。

统一坐标约定为右手系，X 右、Y 上、Z 后，长度为米，角度为度；资产局部原点和朝向在素材包中声明，地面道具默认原点在底面中心。实例变换顺序为缩放、绕 X/Y/Z 旋转、平移；实现时统一欧拉旋转顺序 `XYZ`。包围盒为局部坐标轴对齐盒，碰撞盒可分多个，旋转由实例变换应用。以上是新协议约定，导入原素材时由适配器转换，不能假设原代码的全部对象都天然遵循它。

## 4. 编辑器功能

- **素材库**：筛选内置、已导入和待确认素材；查看来源、依赖、版本及缩略图。新素材导入先进入暂存区，可预览、拒绝或确认。
- **地图视口**：拖放、选择、移动、旋转、缩放、复制、对齐与网格吸附；场景树显示实例层级。显示碰撞、边界、入口、出生点等辅助层并可开关。
- **属性面板**：编辑实例变换、可替换材质槽、种子、碰撞开关和允许暴露的参数。引用素材的修改生成新版本或显式更新实例，不能悄悄改变已保存地图。
- **世界面板**：选择天空预设、时间、雨量、雾、环境光、海和远景；显示当前运行时支持的范围。编辑器以相同渲染器预览，天气参数不写进单个道具。
- **地图检查**：缺失引用、版本不兼容、边界外出生点、出生点与碰撞重叠、无地面、模块入口被堵、预算超限均提示位置；导出前区分错误与警告。
- **工程管理**：保存地图及依赖锁定清单，支持重开、另存和导出；资源缺失时显示占位及具体 ID，不静默替换。撤销/重做覆盖摆放和属性编辑。

## 5. 素材生成与导入

AI 首选输出声明式 JSON：基础几何零件、材质引用、碰撞和绑定点。程序化新底材若超出 v1 现有配方能力，作为单独的**受审核扩展**进入后续版本：需要明确受限接口、独立编译与超时控制、人工审核及兼容性测试；v1 导入器不执行 AI 生成的 JavaScript、GLSL 或其他代码。不能表达的需求应如实报告，不能伪造支持。

导入检查按顺序执行：JSON 和协议版本 → 字段类型及范围 → ID 唯一性和依赖图 → 几何、尺寸、碰撞和绑定点 → 预算 → 隔离渲染预览。缺依赖、循环依赖、路径越界、外链或不可识别字段均拒绝并说明；地图保存时记录精确版本。仅在用户确认后以新版本原子写入素材库，拒绝覆盖内置资源。

第一期预算建议：单道具最多 128 零件、枪械 256 零件、场景模块 512 零件；单包最多 20 个素材、1 MiB JSON，嵌套引用不超过 4 层。预览器还要统计合并后网格、三角面、材质数和加载耗时；实际阈值需在目标机器上测定。高复杂度拆成多个模块，避免地图摆放时频繁重新编译材质或重建几何。

## 6. 地图工程示例

此例展示目标结构；具体 JSON 字段约束以未来的机器可校验 schema 为准。示例 ID 必须先存在于实际素材库，不能直接作为现有实现可运行的地图。

```json
{
  "schema": "along.map/1",
  "id": "user.training_yard",
  "name": "训练场",
  "bounds": { "min": [-20, 0, -20], "max": [20, 10, 20] },
  "world": { "sky": "overcast", "timeHours": 14, "rain": 0.3, "fog": 0.1, "sea": false },
  "instances": [
    { "id": "room_1", "asset": "user.warehouse_corner@1.0.0", "position": [0, 0, 0], "rotation": [0, 0, 0], "scale": [1, 1, 1] }
  ],
  "spawns": [{ "id": "spawn_1", "position": [0, 0, 4], "yaw": 180 }]
}
```

导出时同时保存地图、锁定的素材包和所需内置库版本；重新导入应得到相同的种子、布局、材质和天气。包含外部资源的导出需要确认来源及再分发许可。

## 7. 实施顺序与验收

1. **盘点与适配**：建立独立预览壳，验证并登记至少一种原有材质、道具、PAC-9 和场景片段；记录不可独立复用的内容及原因。验收：相同光照下预览与原场景可比，原始文件哈希不变。
2. **协议与导入**：实现版本化 JSON Schema、依赖解析、限制和错误报告，以及基础几何解释器。验收：指导文档中的示例通过校验并能预览；缺依赖、重复 ID 和非法字段被拒绝。
3. **素材编辑与 AI 导入**：实现材质、道具、枪械、场景模块预览与暂存确认。验收：AI 新建一种材质和一个引用它的道具，重启后可再次使用；不执行任意代码。
4. **地图编辑器**：摆放、碰撞、出生点和世界配置，保存/重开与导出。验收：由原有素材和 AI 素材组装一张地图，重新打开和导出后布局、天气、依赖一致。
5. **运行时接入**：在独立游戏副本接入共享解释器和地图加载，验证出生点、碰撞、画面与编辑器一致；再按需求扩展网络对战。

整个流程先保证可验证的导入和组装，再扩展新几何类型、动画、受审核着色器与更复杂的天气；任何阶段都不直接改写原始 `index.html`。
