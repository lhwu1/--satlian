# 沿线素材生成指导（交给 AI 使用）

本文件供生成沿线编辑器素材的 AI 阅读。用户会提供需求、目标风格、编辑器支持的协议版本和当前素材库清单。你的任务是输出可由未来导入器校验的素材数据，供用户预览、确认后用于地图组装。

**状态：这是拟定的 v1 规范，编辑器、校验器和运行时尚未实现。** 不要声称示例已被程序导入、编译或渲染。用户没有提供的库清单、材质 ID、功能和实现结果一律不能假造；缺少关键信息时先问，或仅使用本包自带的素材并说明假设。

## 1. 工作边界

1. 先判断用户需要 `material`、`prop`、`weapon`、`scene_module` 哪种素材；用户要求多个素材时可在同一包交付，但每个都必须是独立可复用的条目。整张可玩地图是由编辑器组装的工程，不等同于一个房间模块。
2. 优先复用用户提供的已确认素材及其精确版本；缺少的材质可在同一包定义，再由枪械或道具引用。不要擅自改写或覆盖内置素材。
3. 默认做完整的三维物体：有厚度、背面、合理比例、材质和必要的碰撞；房间要考虑地面、墙、门洞与可达空间，不用一张平面冒充建筑。
4. 不修改原始 `index.html`，不输出完整游戏、不嵌入 JavaScript、GLSL、HTML、外链、远程字体或可执行代码。当前声明式几何无法满足时，明确说明限制并提出可实现的简化方案；新着色器属于后续受审核扩展。
5. 保持港口工业风格可作为默认参考：磨损金属、混凝土、涂漆和克制的脏污；用户指定其他风格时遵循用户要求。不要臆称已经使用了原场景的某个未验证材质。

## 2. 请求与交付格式

生成前确认：素材类型、用途与大致尺寸；枪械是否只需第一人称外观；房间是否需可进入、门洞尺寸；用户提供的库清单与版本。如需求足够明确，合理假设并列出；影响是否可用的关键条件缺失时先提问。

输出顺序：

1. 用简短文字列出假设、尺寸、外部依赖与局限。
2. 输出一个完整 `json` 代码块，内容严格符合下面的 `along.asset/1`；禁止注释、尾逗号、NaN 和占位省略号。除示例允许的字段外不添加未知字段。
3. 给出编辑器中的验证步骤：预览视角、尺寸、材质、碰撞/入口或枪械绑定点。未实际运行时明确写“待导入验证”，不要编造测试通过。

机器处理时，JSON 代码块即素材包；说明文字不属于包。包内引用使用 `id@version`，依赖必须在同一包或用户明确提供的素材清单中；不要引入未声明的依赖。包内资产使用各自 ID 和版本；在地图中摆放时同样固定精确版本。

## 3. v1 通用约定

- 编码 UTF-8，单位为米、度；右手系 X 右、Y 上、Z 后。局部物体默认正面朝 `+Z`，底面中心为 `[0,0,0]`；枪械枪口朝 `-Z`。变换为先缩放，再按欧拉 `XYZ` 旋转，最后平移。
- ID 采用 `命名空间.小写名称`，只含小写字母、数字、下划线和一个分隔点，例如 `user.steel_crate`；版本采用 `主.次.补丁`，例如 `1.0.0`。同一包内 `id@version` 不重复，不使用 `builtin` 命名空间生成新素材。
- 根对象只有 `schema`、`assets`；`schema` 固定为 `along.asset/1`。`assets` 为 1 至 20 条。每条有 `type`、`id`、`version`、`name` 及该类型的字段。
- 所有坐标、尺寸和角度为有限数字。尺寸、圆柱半径和高度必须大于 0；颜色为 `#RRGGBB`。包围盒 `min` 每轴小于 `max`，必须包住本体几何；碰撞使用局部盒，地图摆放时随实例变换。
- 只能使用下述几何：`box`、`cylinder`。`box` 字段为 `shape`、`size`、`position`、`rotation`、`material`；`cylinder` 将 `size` 换成 `radius`、`height`，未旋转时轴沿 Y。每个零件均要求显式位置、旋转和精确版本材质引用。
- `bounds` 为 `{ "min": [x,y,z], "max": [x,y,z] }`；`colliders` 为同格式盒数组，空数组表示不阻挡玩家；枪械视图模型默认无地图碰撞。碰撞需要覆盖实体，不得堵住声明的入口。
- 数量限制：道具 128 零件、枪械 256、场景模块 512；单包 JSON 最大 1 MiB，引用嵌套深度最多 4 层。不要通过海量细小零件模拟贴图，优先明确轮廓。

## 4. 各类型字段

### 材质 `material`

字段：`type`、`id`、`version`、`name`、`baseColor`、`roughness`、`metalness`、`wetDarkening`。后三个数值范围均为 0 至 1。v1 表达均匀表面参数，湿润效果的具体映射由运行时实现；要表达现有程序化底材，必须使用库清单中实际存在且支持的引用，不能自行杜撰底材或着色器。

### 道具 `prop`

字段：通用四项加 `bounds`、`parts`、`colliders`。每个零件引用材质；尽量使用少量零件构成完整外形，交付尺寸与 `bounds` 一致。可移动或有交互的道具在 v1 只提供静态外形和碰撞，不伪造动画逻辑。

### 枪械 `weapon`

字段：通用四项加 `bounds`、`parts`、`anchors`、`poses`。`anchors` 包含 `muzzle`、`grip`、`sight` 三个局部坐标；`poses` 包含 `hip` 与 `ads`，每个由 `position`、`rotation` 数组组成。枪械仅描述视觉形状和持枪配置；射速、伤害、弹道和动画由游戏逻辑决定。要有清晰枪口、握把、机匣、枪托或用户要求的对应部件；瞄准时须人工检查 `sight` 对准相机，不能从数据直接保证手感。

### 场景模块 `scene_module`

字段：通用四项加 `bounds`、`parts`、`colliders`、`openings`。`openings` 每项包含 `name`、`center`、`size`，用于标注门洞和检查通行，不会自动挖洞：必须用多块墙构建实际开口。该模块可包含地板、墙、梁和装饰，但天气、天空、全地图出生点由地图工程单独配置。若用户要整个地图，先拆成可复用模块并说明需在编辑器组装。

## 6. 生成前自查

- 包和每个素材的类型、ID、版本齐全；依赖可解析且没有循环或未知字段。
- 尺寸与包围盒匹配，门洞有真实开口；碰撞不堵住门或出生空间；建筑不是单面贴图。
- 零件数在预算内，材质引用精确版本；枪口、握把、准星点和持枪姿态明确。
- 没有代码、外链、假想的内置 ID 或未授权覆盖；说明实际未验证的事项。
